# Cactus Peak Athletic — Context menu specification

Read the [theme foundations](../../themes/cactus-peak-athletic.md), [component index](../../components.md), and [Base UI integration guidance](../../base-ui.md). This specification captures the current theme's authored edits and the preview's resolved values. Preserve these choices when implementing this component; do not replace them with generic library styling or approximate them from the overall theme.

## Anatomy

ContextMenu Root/Trigger around the target region, Portal/Positioner/Popup, and Menu-style items, selection indicators, groups, separators, and optional submenus.

## Layout and geometry

- The reference target is a centered-content surface 280px wide with minimum height 160px; this target size is composition, not a required size for arbitrary receiving content.
- A popup stacks full-width options. Ordinary menus have a 220px reference minimum width capped by available space. The detailed menu uses width 15 × the S text size; a detailed submenu uses 8 × that size. Popup maximum width is min(available width, viewport minus XL spacing, 420px), and maximum height is available height with a 360px fallback. Scroll vertically when necessary.
- Detailed option content uses a grid of a 1em icon/check column, flexible label, and trailing shortcut/submenu column, with XS gaps. Omit the icon column for the whole menu when no row contains an icon/check. Keep labels and shortcuts on one line; shortcuts use the detail typography, Neutral 6, and an S inline-start margin.
- Group labels use XS top/horizontal padding and XXS bottom padding. Separators use a one-sided inset edge, with XXS vertical margins. Options use their own part padding/radii; destructive enabled actions use the Error foreground.
- Use zero native border width. Paint the resolved full edge with a zero-blur box shadow in its supplied inset/outer position, then retain the ordered elevation stack. Keep clipped inner bevels on a separate pointer-transparent overlay inset by the edge width; subtract that inset from each corner radius, clamped at zero. Neither edge width nor focus outline changes layout.

## States and behavior

- Anchor to the primitive’s context position, preserving secondary-click, keyboard context-menu invocation, and dismissal. Resolve shared Menu part assignments and any configured action variant rather than inventing a second menu theme.
- Use primitive item highlighting, checkbox/radio selection, disabled state, typeahead, submenu navigation, and dismissal. A submenu trigger with an open child retains the highlighted appearance. Keep the checkmark and submenu arrow semantic; changing glyphs must not change the action.
- Apply the same theme, color mode, fonts, icon treatment, and motion variables inside the portal. For anchored popups, retain the primitive Positioner, collision handling, available-size variables, and transform origin; the anchor-to-popup offset is the popover part’s gap. Let the primitive own focus, dismissal, and exit mounting; do not copy editor popup pinning or simulated state.
- Respect this component’s anchor/viewport width caps and scroll when content exceeds available height. Animate opacity and popupScale from the primitive transform origin on enter/exit, using Small motion unless this component specifies Large motion.
- Keep the supplied keyboard-focus outline separate from surface shadows. Preserve selected/checked fill when focus coexists; an explicitly authored focus edge may replace only edge width/color, retaining the selected surface, edge placement, and elevation. Disabled styling takes precedence over interaction styling.
- Use the selected icon family/style and semantic glyphs. Inline control icons are normally 1em square and do not shrink. Preserve explicit icon weight; when it is unset, icon weight follows the owning text weight. Decorative glyphs are hidden from accessibility, and icon-only controls have names.

## Resolved specification

The JSON is design data, not a ready-made component. Each variant contains both modes, then parts and their supported states. `tokens` retains the named assignments; `style` contains the complete resolved appearance from the same resolver as the preview, including automatic foregrounds, per-corner radii, opacity, blur, focus treatment, and derived geometry. `css` contains the corresponding base CSS property values (camelCase property names; numeric dimensions are pixels except unitless properties).

Apply a part's relevant properties using its `properties` list and the anatomy/layout rules above. Text-only parts must not acquire a generic surface or padding simply because the base style object contains those fields. Keep themed properties linked to named tokens; use resolved values to reproduce and check derived treatments. `reference` identifies the immediate shared component and `source` its final owner, including the selected button variant. A button reference includes the referenced label's typography and foreground. Reuse that component so its refinements propagate consistently.

Compose shadow-based edges with elevation and separate inner bevels; native borders do not contribute to layout. Preserve the focus outline independently of checked, selected, and open fills. Reproduce the supported combined states described above rather than treating focus as an exclusive selection state. Structural widths can adapt to the receiving layout; authored spacing, typography, geometry, and surface treatments must remain intact.
